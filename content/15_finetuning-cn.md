# 微调

## 根本区别

基于提示的方法通过给模型指令来适应模型，但微调通过调整其权重或参数来适应模型。

它通常用于领域特定的能力，如编码或医疗应用。

虽然微调很强大，但它可能很昂贵且具有挑战性。

## 为什么微调有效

在实践中，大多数人通常微调较小的模型，因为它们需要更少的内存。一个在特定任务上微调的小模型，可能在该任务上优于一个大得多的开箱即用模型。

微调的主要挑战是获取标注数据，这可能很慢且获取成本高，特别是对于领域特定的区域。有些人依赖合成或 AI 生成的数据，但它们的有效性差异很大。

**在考虑微调之前，你应该始终从严格的提示实验开始。**

## 微调策略

虽然微调周围的很多事情——决定是否微调、获取数据和维护微调模型——都很困难，但实际的微调过程更加直接。你需要选择三件事：基础模型、微调方法和微调框架。

### 基础模型：起点很重要

在 AI 项目开始时，当你仍在探索任务的可行性时，从你能负担得起的最强大的模型开始是有用的。如果这个模型难以产生好的结果，较弱的模型可能表现更差。如果最强的模型满足你的需求，你可以探索较弱的模型，使用初始模型作为比较基准。

对于微调，不同项目的起始模型各不相同。有两条主要的开发路径：

#### 渐进路径
1. **测试你的微调代码**使用最便宜和最快的模型，确保代码按预期工作
2. **测试你的数据**通过微调一个中等模型。如果训练损失不随更多数据下降，可能有问题
3. **运行实验**使用最好的模型，看看你能把性能推到多远
4. **绘制边界：** 一旦你有了好的结果，用所有模型进行一次训练运行以绘制价格/性能边界，并选择对你的用例最有意义的模型

#### 蒸馏路径
1. **强势开始：** 从一个小数据集和你能负担得起的最强模型开始。用这个小数据集训练可能的最佳模型。因为基础模型已经很强，它需要更少的数据来实现良好的性能
2. **生成更多数据：** 使用这个微调模型生成更多训练数据
3. **训练更便宜：** 使用这个新数据集训练更便宜的模型

因为微调通常在提示工程实验之后进行，到你开始微调时，理想情况下，你应该对不同模型的行为有相当好的理解。你应该根据这种理解计划你的微调开发路径。

### 微调方法：完全微调 vs 适配器技术

像 LoRA 这样的适配器技术具有成本效益，但通常不能提供与完全微调相同水平的性能。如果你刚开始微调，尝试像 LoRA 这样的方法，稍后再尝试完全微调。

使用的微调方法也取决于你的数据量。根据基础模型和任务，完全微调通常需要至少数千个示例，通常更多。然而，PEFT（参数高效微调）方法可以用小得多的数据集显示良好的性能。如果你有一个小数据集，如几百个示例，完全微调可能不会优于 LoRA。

在决定微调方法时，要考虑你需要多少个微调模型以及你想如何为它们提供服务。像 LoRA 这样的基于适配器的方法允许你更高效地为共享相同基础模型的多个模型提供服务。使用 LoRA，你只需要提供一个完整模型，而完全微调需要提供多个完整模型。

### 微调框架：API vs 自定义解决方案

**微调 API** 是最简单的微调方式。你上传数据，选择一个基础模型，然后得到一个微调模型。像模型推理 API 一样，微调 API 可以由模型提供商、云服务提供商和第三方提供商提供。

这种方法的局限性：
- 你被限制在 API 支持的基础模型
- API 可能不会公开你可以用于最佳微调性能的所有参数

微调 API 适合那些想要快速简便的人，但对于想要更多定制的人来说可能会令人沮丧。

**自定义框架**给你更多灵活性。你可以使用 LLaMA-Factory、unsloth、PEFT、Axolotl 和 LitGPT 等框架进行微调。它们支持广泛的微调方法，特别是基于适配器的技术。如果你想进行完全微调，许多基础模型在 GitHub 上提供他们的开源训练代码，你可以克隆并用你自己的数据运行。

自己进行微调给你更多灵活性，但你必须配置必要的计算资源。如果你只做基于适配器的技术，中档 GPU 对于大多数模型可能就足够了。如果你需要更多计算资源，你可以选择一个与你的云提供商无缝集成的框架。

要使用多台机器微调模型，你需要一个帮助你进行分布式训练的框架，如 DeepSpeed、PyTorch Distributed 和 ColossalAI。

## 微调超参数

根据基础模型和微调方法，有许多超参数你可以调整以提高微调效率。以下是最重要的：

### 学习率：步长问题

学习率决定了模型的参数在每个学习步骤中应该改变多快。如果你把学习想象成寻找通向目标的路径，学习率就是步长。如果步长太小，可能需要太长时间才能达到目标。如果步长太大，你可能会越过目标，模型可能永远不会收敛。

不存在普遍最优的学习率。你必须实验不同的学习率，通常在 1e-7 到 1e-3 的范围内，看看哪个效果最好。一个常见的做法是取预训练阶段结束时的学习率，并乘以 0.1 到 1 之间的常数。

**阅读损失曲线：** 如果损失曲线波动很大，很可能学习率太大。如果损失曲线稳定但下降需要很长时间，学习率可能太小。在损失曲线保持稳定的情况下尽可能提高学习率。

你可以在训练过程中使用**学习率调度**来改变学习率——这些算法决定学习率在整个训练过程中应该如何变化（开始时较大的学习率，接近结束时较小）。

### 批量大小：内存 vs 稳定性权衡

批量大小决定模型在每个步骤中从多少示例学习来更新其权重。太小的批量大小，如少于八个，可能导致训练不稳定。较大的批量大小有助于聚合来自不同示例的信号，从而产生更稳定和可靠的更新。

一般来说，批量大小越大，模型通过训练示例的速度越快。然而，批量大小越大，运行模型所需的内存越多。因此，批量大小受你使用的硬件限制。

这就是你看到成本与效率权衡的地方。更昂贵的计算资源允许更快的微调。

**梯度累积：** 截至本文撰写时，计算资源仍然是微调的瓶颈。通常，模型如此之大，内存如此受限，以至于只能使用小批量大小。这可能导致模型权重更新不稳定。为了解决这个问题，你可以在多个批次中累积梯度，并在累积足够可靠的梯度后更新模型权重，而不是在每个批次后更新模型权重。

### 训练轮数：每个示例看多少次

一个训练轮数是对训练数据的一次遍历。训练轮数决定每个训练示例被训练多少次。

小数据集可能比大数据集需要更多的训练轮数。对于有数百万示例的数据集，1-2 轮可能就足够了。有数千个示例的数据集在 4-10 轮后可能仍然看到性能改进。

**使用损失曲线指导训练轮数：** 如果训练损失和验证损失仍在稳步下降，模型可以从更多轮数（和更多数据）中受益。如果训练损失仍在下降但验证损失增加，模型在训练数据上过拟合，你可能尝试降低训练轮数。

### 提示损失权重：从指令 vs 响应中学习

对于指令微调，每个示例由提示和响应组成，两者都可以在训练期间对模型的损失做出贡献。然而，在推理期间，提示通常由用户提供，模型只需要生成响应。因此，响应词元在训练期间应该比提示词元对模型的损失贡献更多。

提示损失权重决定提示相对于响应应该对这个损失贡献多少。如果这个权重是 100%，提示对损失的贡献与响应一样多，意味着模型从两者中同等学习。如果这个权重是 0%，模型只从响应中学习。通常，这个权重默认设置为 10%，意味着模型应该从提示中学习一些，但主要从响应中学习。
