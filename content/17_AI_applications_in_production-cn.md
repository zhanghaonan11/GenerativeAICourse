# 构建生产级 AI 应用

到目前为止，我们已经探索了构建 AI 应用时所有重要的概念。

本课程的这一部分将重点介绍在真实生产环境中构建 AI 应用所需的条件和一些最佳实践。

## 1. 护栏：保护你的 AI 系统

我们之前已经解释过，你的 AI 应用可能容易受到使用 AI 的恶意攻击，比如提示注入或越狱。你的用户可能会暴露你不想泄露的私人信息。请注意，许多第三方 API（如 OpenAI）为你提供了许多开箱即用的护栏。

### 输入护栏：第一道防线

这些护栏可以防止向外部 API 泄露私人信息，并防止执行可能危害系统的恶意提示。有许多工具可以自动检测敏感数据（由你指定），这些工具通常使用 AI，你可以阻止这些数据被发送到模型。

**真实案例 - 医疗平台：** 一个医疗 AI 助手需要防止 PHI（受保护的健康信息）被发送到外部 LLM API：

**实施方案：**
- 构建自定义 NER（命名实体识别）模型来检测患者姓名、社会安全号码、病历号
- 使用正则表达式模式匹配结构化数据，如电话号码和地址
- 实施关键词阻止，针对药物名称和诊断代码
- 设置实时扫描，延迟要求为 50 毫秒

**检测规则：**
- 社会安全号码：`\d{3}-\d{2}-\d{4}` 模式匹配
- 患者 ID：针对医院特定编号的自定义格式识别
- 医学术语：阻止 2,847 个特定药物名称和 1,203 个诊断代码
- 个人标识符：姓名与患者数据库交叉引用

**结果：** 第一个月防止了 234 次 PHI 泄露，降低了合规风险，在保持 HIPAA 合规的同时实现了外部 AI 的使用。

**常见输入护栏类别：**
- **PII 检测：** 姓名、地址、电话号码、电子邮件地址、社会安全号码
- **财务数据：** 信用卡号、账户号、路由号
- **企业机密：** 产品名称、财务数据、战略计划
- **提示注入：** 试图覆盖系统指令的尝试
- **恶意内容：** 试图生成有害或非法内容的尝试

### 输出护栏：AI 响应的质量控制

这是为了捕获不符合你标准的输出。比如模型返回不当信息，甚至是仇恨或非法信息。需要注意的一点是，输出护栏在流式完成模式下可能效果不佳。

**真实案例 - 客户服务 AI：** 一家电信公司为其客户服务聊天机器人实施了输出过滤：

**多层过滤：**
1. **内容安全：** 使用 Azure 内容安全 API 检测仇恨言论、暴力、自残内容
2. **品牌合规：** 在 10,000 个适当与不适当响应示例上训练的自定义分类器
3. **准确性验证：** RAG 引用检查器，确保响应基于知识库
4. **语调分析：** 情感分析，确保响应保持专业、有帮助的语调

**实施细节：**
- 实时处理，平均延迟 80 毫秒
- 置信度阈值：阻止毒性评分 >70% 的响应
- 后备响应：当 AI 输出被阻止时使用预先编写的安全响应
- 人工升级：标记多个响应被阻止的对话

**结果：**
- 不当响应减少 94%
- 客户满意度从 3.2 提高到 4.1（满分 5 分）
- 防止了潜在的品牌损害事件
- 估计节省了 120 万美元的声誉管理成本

**流式处理挑战：** 输出护栏在流式响应中更难实施，因为你无法在发送之前分析完整的响应。解决方案包括：
- 句子级过滤（在生成每个句子时检查）
- 滑动窗口分析（持续分析最后 N 个 token）
- 保守设置（流式处理时使用更高的阻止阈值）

## 2. 模型路由器和网关：智能流量管理

### 路由器：为正确的任务选择正确的模型

这是 AI 应用中的常见模式。不是对所有查询使用一个模型，而是使用不同的模型。实际上，根据经验，大多数 AI 应用对不同的任务使用不同的模型。这可以帮助节省成本，你可以对更简单的查询使用更便宜的模型。

路由器由预测用户意图的逻辑组成，根据该意图，查询被路由到适当的模型（同样通常使用 AI）。有一些开箱即用的解决方案，或者你可以用小型语言模型构建自己的路由器。

**真实案例 - 电商平台：** 一家在线零售商为其客户查询构建了复杂的路由系统：

**意图分类：**
- **简单问题**（43% 的查询）："我的订单状态是什么？" → 路由到快速、便宜的模型（GPT-3.5）
- **产品推荐**（31% 的查询）："帮我找一台游戏笔记本电脑" → 路由到专门的 RAG 系统
- **复杂支持**（18% 的查询）："我需要退货但网站不让我操作" → 路由到高级模型（GPT-4）+ 人工升级
- **技术问题**（8% 的查询）："如何设置这个路由器？" → 路由到技术文档模型

**路由器实施：**
- 使用 500 参数模型构建轻量级分类器（推理成本：每次查询 0.0001 美元）
- 训练数据：来自支持工单的 50,000 个标注客户查询
- 实时预测，延迟 25 毫秒
- 置信度阈值：如果分类置信度 <85%，则路由到高级模型

**成本影响：**
- 路由前：每次查询平均 0.012 美元（所有查询都发送到 GPT-4）
- 路由后：每次查询平均 0.004 美元（成本降低 67%）
- 月度节省：89,000 美元，响应质量相同或更好
- 由于简单查询响应更快，客户满意度提高

**高级路由策略：**
- **基于负载的路由：** 根据当前 API 负载路由到不同模型
- **用户层级路由：** 高级客户获得更好的模型
- **上下文感知路由：** 根据对话历史和复杂性进行路由
- **A/B 测试集成：** 将一定比例的流量路由到实验模型

### 网关：统一模型管理

这允许你以安全的方式连接到不同的模型。它是不同模型的统一接口，使代码维护更容易。你通常可以在网关级别应用限流、跟踪使用情况等。

**真实案例 - 金融服务公司：** 一家投资公司构建了模型网关来管理其组织内的 12 个不同 AI 模型：

**网关架构：**
- **单一 API 端点：** 所有应用程序连接到一个 URL，无论底层模型是什么
- **认证：** 带有基于角色的模型访问的 JWT 令牌
- **速率限制：** 不同用户层级和模型有不同的限制
- **模型抽象：** 相同的请求格式适用于 OpenAI、Anthropic、Google 和内部模型

**实施的功能：**
- **自动故障转移：** 如果主模型宕机，自动路由到备份
- **使用跟踪：** 按部门、用户和模型跟踪成本
- **请求日志：** 存储所有请求/响应用于审计和训练
- **模型版本控制：** 支持同一模型的多个版本，逐步推出

**业务影响：**
- **开发者生产力：** 新模型的集成时间从 2 周减少到 2 小时
- **成本管理：** 跨所有团队的集中计费和使用分析
- **合规性：** 审计日志和安全控制的单一控制点
- **可靠性：** 99.7% 的正常运行时间，带自动故障转移（相比直接 API 调用的 94%）

**技术实施：**
```python
# 示例网关请求 - 无论模型如何，格式相同
POST /gateway/v1/chat/completions
{
    "model": "best-for-finance",  # 网关解析为实际模型
    "messages": [...],
    "user_tier": "premium",       # 影响路由和速率限制
    "department": "trading"       # 用于成本跟踪
}
```

## 3. 缓存：速度和成本优化

缓存在软件开发中并不新鲜。它一直被用来减少延迟和成本（避免持续的数据库查询）。在 AI 方面有不同的缓存技术。

### 精确缓存：完美匹配

例如，如果用户要求模型总结一个产品，系统会检查缓存中是否存在这个确切产品的摘要。这用于避免持续的向量搜索。这可以使用像 Redis 这样的内存存储来实现。

**真实案例 - 新闻聚合平台：** 一个新闻网站为文章摘要实施了精确缓存：

**实施方案：**
- **缓存键：** 文章 URL + 摘要长度参数的 SHA-256 哈希
- **存储：** Redis 集群，TTL 为 72 小时（新闻很快过时）
- **缓存大小：** 500GB，存储约 200 万篇文章摘要
- **命中率：** 67% 的摘要请求从缓存提供

**性能影响：**
- **延迟：** 缓存命中响应 15 毫秒，AI 生成需要 2.3 秒
- **成本节省：** 每月节省 23,000 美元的 LLM API 调用
- **用户体验：** 热门文章即时加载
- **可扩展性：** 在重大新闻事件期间处理了 10 倍的流量峰值

**缓存策略：**
- 对热门文章进行主动缓存（在用户请求之前缓存）
- 智能驱逐：删除浏览量 <10 的文章摘要
- 地理分布：在多个区域缓存热门文章

### 语义缓存：相似意图匹配

即使查询不完全相同，只要语义相似也可以使用缓存项。这需要向量数据库来存储缓存查询的嵌入，因此更复杂且计算密集。速度和成本可能不值得。

**真实案例 - 法律研究平台：** 一个法律 AI 助手为案例法研究实施了语义缓存：

**挑战：** 律师经常以不同方式提出类似问题：
- "加州违约的先例是什么？"
- "给我看加州关于合同违约的案例法"
- "查找加州法院的违约案例"

**实施方案：**
- **向量存储：** Pinecone 数据库存储查询嵌入
- **相似度阈值：** 如果余弦相似度 >0.85 则缓存命中
- **嵌入模型：** text-embedding-ada-002 用于一致的表示
- **缓存评分：** 按查询流行度和新近度加权

**性能分析：**
- **缓存命中率：** 34% 的查询与语义相似的先前查询匹配
- **每次命中成本：** 0.15 美元（嵌入查找 + 向量搜索）
- **每次未命中成本：** 3.20 美元（完整的 RAG 法律研究）
- **盈亏平衡：** 语义缓存在命中率 >4.6% 时盈利

**结果：**
- 缓存命中的平均响应时间从 8.2 秒减少到 1.7 秒
- 整体计算成本降低 31%
- 通过更快的研究结果改善用户体验
- 挑战：当法律先例变化时，缓存失效很复杂

**语义缓存适用场景：**
- 高成本 AI 操作（复杂 RAG、长文档）
- 重复的用户模式（客户支持、研究）
- 稳定的知识领域（法律、医疗、技术文档）

**避免语义缓存的场景：**
- 低成本 AI 操作（简单聊天完成）
- 高度动态的内容（实时数据、突发新闻）
- 隐私敏感的查询（每个用户需要新鲜结果）

## 4. 可观测性：监控 AI 性能

同样，可观测性是软件工程中的通用实践。特定于 AI，通常是每个请求的输入和输出 token 数量、格式失败（如果你期望 JSON 输出，跟踪模型给出无效 JSON 的频率）。对于开放式生成，考虑简洁性、创造性或积极性等指标——许多这些指标可以使用 AI 评判器计算。

### 核心 AI 指标

**真实案例 - SaaS 平台：** 一个带有 AI 功能的项目管理工具跟踪全面的指标：

**Token 和成本指标：**
- **每请求输入 token：** 平均 342 个 token，第 95 百分位 1,247 个 token
- **每请求输出 token：** 平均 156 个 token，最大上限 500
- **每请求成本：** 平均 0.0034 美元，环比下降 12%
- **模型利用率：** GPT-4: 23%，GPT-3.5: 61%，Claude: 16%

**质量指标：**
- **格式合规性：** 94.3% 的 JSON 响应有效（目标：>95%）
- **响应相关性：** AI 评判器对响应评分 1-5，平均 4.2
- **引用准确性：** 87% 的 RAG 响应包含有效引用
- **幻觉率：** 3.1% 的响应包含无根据的声明

### 高级可观测性模式

**用户行为分析：**
- **对话长度：** 平均 3.4 轮，15% 的用户有 >10 轮对话
- **提前终止：** 8% 的用户在响应中途停止生成（表明质量差）
- **重试率：** 12% 的用户重新生成响应（质量指标）
- **功能采用：** 67% 的活跃用户使用 AI 功能

**性能监控：**
- **端到端延迟：** P50: 1.2 秒，P95: 4.7 秒，P99: 12.3 秒
- **模型延迟：** 与 RAG 检索和护栏处理分开跟踪
- **错误率：** 模型 API 错误（2.1%），超时错误（0.8%），护栏阻止（1.4%）
- **可用性：** 所有 AI 功能 99.2% 正常运行时间

**业务影响指标：**
- **用户参与度：** AI 用户的留存率比非 AI 用户高 34%
- **支持工单减少：** AI 启用用户的支持工单减少 23%
- **功能满意度：** AI 功能的 NPS 评分为 67（相比整体产品 NPS 45）
- **收入影响：** AI 功能推动付费计划转化率提高 18%

### RAG 特定可观测性

**真实案例 - 知识管理平台：** 一个带有 RAG 功能的企业搜索工具：

**检索质量：**
- **检索延迟：** 向量搜索：45 毫秒，语义重排序：120 毫秒
- **块相关性：** 人工标注员对前 3 个块评分，78% 相关性得分
- **覆盖分析：** 23% 的查询需要来自多个来源的信息
- **索引新鲜度：** 跟踪搜索结果中的数据年龄（平均 4.2 天）

**答案质量：**
- **引用率：** 91% 的响应包含至少一个引用
- **引用准确性：** 83% 的引用实际支持答案
- **完整性：** AI 评判器对答案完整性评分，平均 4.1/5
- **信息冲突：** 当来源相互矛盾时标记（7% 的查询）

### 实施工具和平台

**监控堆栈：**
- **应用指标：** DataDog 用于延迟、吞吐量、错误率
- **AI 特定指标：** Weights & Biases 用于模型性能跟踪
- **用户分析：** Mixpanel 用于用户行为和功能采用
- **成本跟踪：** 自定义仪表板聚合所有模型提供商的使用情况

**告警配置：**
- **即时告警：** 错误率 >5%，延迟 >10 秒，护栏阻止 >20%
- **每日告警：** 成本飙升 >30%，质量评分下降 >10%
- **每周报告：** 使用趋势、成本优化机会、质量改进

**仪表板设计：**
- **高管仪表板：** 高级指标、成本趋势、业务影响
- **工程仪表板：** 技术指标、错误分析、性能优化
- **产品仪表板：** 用户行为、功能采用、质量趋势

成功的 AI 可观测性的关键是平衡技术指标和业务成果。跟踪对你特定用例重要的内容，并始终将 AI 性能与用户满意度和业务结果联系起来。
